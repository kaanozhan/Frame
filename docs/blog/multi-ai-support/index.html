Supporting Claude, Codex, and Gemini in One App

Each AI coding tool has its own way of reading project context. We needed a unified approach that works with all of them.

The Challenge

Frame's context preservation system is built around .frame/AGENTS.md — a single file containing all project instructions, navigation rules, and conventions. But each AI tool reads context differently:

  • Claude Code loads every .claude/rules/*.md automatically at session start
  • Codex CLI has no standard for reading project files

We needed each tool to get the same project context, without maintaining separate instruction files — and without Frame planting anything in the project root.

Solution: A Generated Rule File + Wrapper Scripts

Claude Code — .claude/rules/frame.md

Claude Code loads its rule files natively, so Frame writes one and keeps it in step with the single source of truth:

.frame/AGENTS.md          ← The actual file (single source of truth)
.claude/rules/frame.md    ← Generated copy, rewritten whenever AGENTS.md changes

One file to maintain, and nothing in the project root: an existing CLAUDE.md is the user's, and Frame never touches it.

Codex CLI — Wrapper Script

Codex CLI doesn't have a native file-reading convention. Our first attempt was to use a --system-prompt flag — but Codex CLI doesn't have that flag.

The final solution: a wrapper script in .frame/bin/codex that sends "Read .frame/AGENTS.md" as the initial prompt:

#!/bin/bash
# .frame/bin/codex - Frame wrapper for Codex CLI
AGENTS_FILE=".frame/AGENTS.md"
if [ -f "$AGENTS_FILE" ]; then
  codex "Please read .frame/AGENTS.md and follow the project instructions."
else
  codex "$@"
fi

When Frame starts Codex CLI, it uses this wrapper instead of the bare codex command. The AI reads the file and gets full project context.

Key Insight

Instead of trying to pass system prompts via flags (which vary per tool), simply ask the AI to read the .frame/AGENTS.md file. This approach is tool-agnostic and works with any AI coding assistant.

Switching Between Tools

In Frame's UI, switching between AI tools is a single click from the toolbar dropdown. Each tool gets proper context injection automatically:

  • Select Claude → runs claude directly (loads .claude/rules/frame.md natively)
  • Select Codex → runs via the .frame/bin/codex wrapper (injects .frame/AGENTS.md)

Same project context, different AI engines. Use whichever tool is best for the task at hand.

Node.js Version Gotcha

One unexpected issue: Gemini CLI's dependency string-width uses the /v regex flag, which requires Node.js 20+. With Node.js 18, it crashes with SyntaxError: Invalid regular expression flags.

If you're adding Gemini CLI support, make sure you're on Node.js 20 or later. And if you use nvm, don't forget nvm alias default 20 — otherwise terminals spawned by Electron still use the old default version.

Workspaces shipped Conductor-style: a project's sidebar lists a `main` row (the main checkout, terminals allowed, no PR flow) and one row per workspace = branch + linked worktree outside the repo at `~/frame/workspaces/<repo>/<color>` + its terminals. ⌘⇧N creates one from a fresh branch `<prefix>/<color>` off fetched `origin/<base>` (`--no-track`) or an existing branch, copies gitignored files matching `settings.workspaces.copyFiles` (default `.env*`), runs the setup script in a visible `setup` tab and opens the agent when it returns to the shell. Selecting a row scopes terminals (per-workspace cap 9), file tree, git watch, branch label/picker and sessions to its folder. Archive never auto-commits (dirty → commit with message / discard / cancel), closes the workspace's terminals, removes the folder, keeps the branch; restore recreates it and reruns setup only.
Why this path: location belongs to what runs, not to specs (user rejected spec-bound location); worktrees live outside the repo because in-repo ones borrow the main checkout's node_modules and make Claude load the main CLAUDE.md on top of the branch's; records sit in `~/.frame/workspaces.json` (`projects[i].workspaces`, machine-local, no migration) rather than a new file. Rejected: separate remote window, registering worktrees as projects, Conductor's right git panel in v1 (→ workspace-review), city names (colors chosen).
Rules for future work: `projectPath` is the project identity; `state.getWorkspaceRoot()` is where checkout-bound views point — never load a checkout view from `projectPath` directly. Main keeps the pre-workspace localStorage keys; other workspaces key as `<projectPath>#<id>`. Records carry `location: 'local'` so self-hosted can add servers without a migration. Code "workspace" now means only branch + worktree; the old project registry is `projectRegistry.js` (file name `workspaces.json` kept). Untracked-but-not-ignored files are never copied (uncommitted work does not travel). Orchestration was left out of scope and not adapted.
Followups: the Project Settings overlay keeps showing the previous project's values when the project changes while it is open (pre-existing); a window can disappear on reload while agent terminals run (seen twice in isolated runs, not traced).

# Plan — Frame's own scripts stay out of the user's repo

## Architecture

### Resolved plan-time decisions

- **Git sharing row copy — minimal correction** *(business, asked)*. The
  description stops naming the `.frame/` folder and names the project's Frame
  context instead; it does not add a clause about Frame's scripts. Rationale:
  once the folder framing is gone the row no longer implies the scripts are
  part of the choice, and a promise about what is *not* committed is a claim
  the row would then have to keep true forever. **Narrows S8**, whose original
  wording asked for an enumeration ("specs, tasks, notes, instructions"); the
  spec's criterion was corrected to match this decision.
- **`FRAME_TRACKED_DERIVED` survives with one entry** *(technical, asked)*.
  `['STRUCTURE.json']`. Rationale: removing the list means moving
  `STRUCTURE.json` into the `data` class, which asserts "STRUCTURE.json is
  project-authored data" — a claim this spec explicitly put Out of Scope.
- **Test posture: the required inversion only** *(technical, asked)*.
  `test/gitSharing.test.js:91` asserts today that `bin/` is absent from the
  managed block; that assertion is inverted and its message rewritten. No new
  assertions in `test/frameProjectInit.test.js`. Rationale: chosen by the user;
  the init path writes the same generated block, so the inverted assertion
  already covers the mechanism that produces it.
- **`bin/` returns to the `runtime` class** *(technical, silent)*. Dropping
  `bin/` from `FRAME_TRACKED_DERIVED` alone is not enough, and removing it from
  `derived` without a destination would be actively wrong: the block is built as
  `runtime ∪ (derived − FRAME_TRACKED_DERIVED)`, so an entry in neither list
  appears in neither side and is ignored nowhere. `runtime` is also the class
  `non-invasive-overlay` D6 assigned before T15 moved it, so this is the literal
  reversal rather than a third position.
- **The T15 reversal is recorded in the code comment** *(technical, silent)*.
  `frameConstants.js:76-80` is where T15's rationale lives today; a future reader
  meets the comment, not the spec archive. The comment is rewritten to name what
  was reversed and why both original rationales lapsed.
- **`index.html` collision accepted** *(technical, silent)*. `spec-context`
  flags it as IN-FLIGHT for `audit-q3-performance-resources` (phase
  `implementing`). T01–T09 of that spec are completed and its only open task,
  T10, is a measurement pass that writes no code. This edit is one `<p>` inside
  the Project Settings block, disjoint from that spec's perf work.
- **The empty `.claude/settings.json` shell is fixed here** *(business, asked)*.
  Added 2026-08-28 after the spec's first nine tasks landed, from an observed
  `repo` → `local` switch: `removeSpecHintHook` strips Frame's hook entries and
  writes back what is left, which in a Frame-initialised project is literally
  `{}`, and nothing excludes `.claude/settings.json` in `local` mode — by
  design, since in `repo` mode it is the team's shared file. Scoped to
  deleting the shell only while it is **untracked**; a file the user committed
  stays, because untracking is theirs to do (`gitSharing.js:15-20`).
  **Extends Files and Footprint** with `src/main/frameProject.js` and
  `src/main/gitExclude.js`.

- **Frame's own `.frame/.gitignore` is committed with the change** *(technical,
  silent)*. It is a tracked file in this repo, regenerated by
  `gitSharing.reconcile` on the next project open. It is a Frame meta file, so
  it is deliberately absent from **Footprint** per the orchestrator rule, and
  appears in **Sequencing** instead.

### The mechanism

Nothing in the generator changes. `getFrameGitignoreBlock`
(`frameTemplates.js:859-865`) already builds the managed block as
`runtime ∪ (derived − FRAME_TRACKED_DERIVED)` and is the single consumer of
`FRAME_FILE_CLASSES` in the codebase. This spec changes only its inputs:

```
before                                   after
  runtime:  [runtime/, worktrees/, …]      runtime:  [runtime/, worktrees/, …, bin/]
  derived:  [STRUCTURE.json, bin/, …]      derived:  [STRUCTURE.json, index/, …]
  TRACKED:  [STRUCTURE.json, bin/]         TRACKED:  [STRUCTURE.json]
  → block excludes bin/                    → block contains bin/
```

`bin/` appears in exactly two places in the whole codebase
(`frameConstants.js:58` and `:81`), so the blast radius is those two lines plus
the comment that explains them.

Everything downstream is already shaped for a `bin/`-less checkout and is
touched by nothing here: the hook guard's `[ ! -f … ] ||` form
(`frameTemplates.js:869-882`), `binDirFor`'s absolute path for worktrees
(`orchestrationManager.js:92`), and the pre-commit snippet's
`--git-common-dir` fallback (`frameTemplates.js:1055-1064`). `copyParserScripts`
(`structureBootstrap.js:41-112`) keeps running on every project open
(`frameProject.js:1225`) — the scripts still land in every checkout; only git's
view of them changes.

No detection, warning row or migration ships: `git tag --contains a8c1c8c` is
empty and `v2.6.0` predates T15, so no released build tracks `bin/`.

Specs now live in workspaces: a new spec runs in the selected workspace (from main Frame creates one first, runs its setup without an agent), and every spec command selects the spec's workspace and stages its prompt in that worktree, so `.frame/specs/<slug>/` is written and committed on the branch and lands in the same PR as the code. The project still shows one list: `specManager` keeps a slug → checkout map (main + active workspaces, workspace copy wins a clash) and resolves every spec folder through `getSpecDir`, so status, phase, reports, rename and the tasks.md import act on the right checkout with unchanged signatures; entries carry `workspace` and the specs board, spec panel, Home and workspace rows show it (opening selects the workspace). Task state never forks: templates get `{tasks_path}` = the main checkout's tasks.json (the terminal hook finds it through `git rev-parse --git-common-dir`). Frame tooling (`.frame/bin`, `runtime/commands`, `index`, plus `.claude/settings.local.json` in local mode) is copied into a worktree on create/restore/select and before each spec command, so hooks work there unchanged. Local gitSharing mode hands spec folders back to main before archive removes the worktree. Also fixed: spec commands dispatched while a workspace was selected told the agent a relative prompt path that only existed in main.
Why this path: one resolution point (getSpecDir + location map) over a root parameter on ~20 call sites; copies over symlinks (Windows privileges, realpath'd __dirname); absolute {tasks_path} over task state in the spec folder (smaller change, no merge conflicts). Rejected: asking "workspace or main" per new spec; keeping specs in main in local mode.
Rules for future work: build spec paths only through `frameStore` with the slug's checkout (`specRoot`); stage anything an agent reads by relative path in the agent's root; a new template placeholder must also be filled in `scripts/spec-command-hint.js` (drift guard). The spec index stays built from main (merged specs only).
Followups: the window can vanish on reload while agent terminals run — the log shows a throw in `uiZoom.attachWindow` from `createWindow` (src/main/index.js:438) on re-create; a hand-made spec gets bound to a waiting Spec Creator lane (existing single-new-slug binding).

Workspaces got their way out. Each workspace row shows ●uncommitted, ↑unpushed (vs upstream, else origin/<base>), ↓behind its base, and its PR (#n coloured by draft/open/merged/closed, a checks dot, comments) from state that main's `workspaceGitState` reads with the user's git and `gh` and pushes as `WORKSPACE_GIT_STATE` — one visibility-gated 3-minute poller for the watched project, plus focus, explicit refresh, workspace changes and every action. The row menu (and palette) offers Push (first push `-u origin <branch>`, confirm when dirty), Create Pull Request… (⌘⌥P; a dialog prefilled by `prFlow.composePr` from the workspace's spec — Why/What/Done/spec path — else commit subjects; edit, draft; push first, then `gh pr create … --body-file -`), Fix Failing Checks (a prompt naming the checks and `gh pr checks` / `gh run view --log-failed` to a new agent lane in the workspace), Open on GitHub, and Merge (only when ready; method from Project Settings or the repo's first allowed squash → merge → rebase; then the main checkout fast-forwards when on the base with no tracked changes, and the workspace archives when "Archive after merge" is on).
Why this path: Frame composes the PR text (instant, no model call, the "why" is in the spec) over agent-drafted text; main owns state over per-row renderer polling. Rejected: asking the merge method / archive every time; ⌘⇧P (palette) and ⌘⇧R (force reload) as shortcuts.
Rules for future work: every git/gh call that carries user text or branch names is argv (`runGh`, `execGitArgs`) with free text on stdin; never `--force`, never push the base (`isPushable`), never commit for the agent; gh runs only for branches that are pushed or had a PR. `runGh` always closes stdin. Tested end to end with a fake `gh` on the scratch login PATH — no real GitHub was touched.
Followups: review comments and diff (workspace-review); updating from the base (update-from-base); the Project Settings overlay still shows the previous project when the project changes while it is open.

1 · What & why

Frame currently writes six files into the root of every project it manages and consumes the project's own CLAUDE.md into a symlink. This plan moves the five data/instruction files (AGENTS.md, tasks.json, STRUCTURE.json, PROJECT_NOTES.md, QUICKSTART.md) under .frame/, stops touching user-owned instruction files, and replaces the symlink with a one-line .claude/rules/frame.md that imports .frame/AGENTS.md — a mechanism Claude Code loads natively at session start, for subagents and -p runs alike. Hooks stay in .claude/settings.json exactly as today. A solo/team setting (gitSharing), a consented migration for existing projects, a data-centric storage seam (frameStore), a stable projectId and a file-class table prepare the later database/cloud layer without changing how anything behaves now.

The obvious alternative — the June spec's and PR #116's "inject context at launch time via wrappers/PATH/shell init" — was reviewed and rejected: it turns a guaranteed file-based mechanism into a best-effort one (no subagents, no context outside Frame, alias/PATH failure modes) and puts repository content on every terminal's PATH. The other alternative, leaving the root layout as it is, keeps the problems the spec names (root pollution, consumed CLAUDE.md, no solo/team distinction, no seam). The chosen shape keeps the data move and the native delivery.

Architectural notes
  • No write-behind cache: agents edit these files with their own tools; tasksManager's directory watcher now watches frameStore.metaDir() and must see every change. The existing mtime+size parse cache is a read cache, kept.

3 · Decision story

Business decisions

D1 · What is the default sharing mode when a project is initialized?
chosen
repo pre-selected, local selectable
Shared context and orchestration work out of the box; a user who wants a clean tree picks local.
local pre-selected / no pre-selection
Zero-touch by default, but team and orchestration flows are one step away; asking every time adds friction.
Why: Frame's value is shared context; a repo that already tracks .frame/ is repo regardless of the radio.
D2 · STRUCTURE.json is derived — keep it tracked or ignore and regenerate?
chosen
Stays tracked
Teammates and worktrees have the map immediately; pre-commit hook keeps it current.
Ignore + regenerate on open
Cleaner diffs, but no map until first open and a dependency on the staged parser.
Why: least risk now; "derived → ignored" is a separate later decision.
D3 · Where do the sharing control and "Remove Frame" live?
chosen
Settings → Workflow
Existing per-project section and IPC pattern; no new modal.
New Project Settings modal (PR #116 style)
More discoverable, but a new surface, CSS and projectSection changes.
Why: one place for per-project workflow switches, smallest footprint.
D4 · How is migration consent collected?
chosen
Renderer modal on project selection
Can list moves, show progress and a persistent receipt; appears only for the project the user opened.
Electron dialog / startup sweep
Native dialog cannot show a receipt; a sweep touches projects the user is not looking at.
Why: a receipt with moved/restored/backed-up/review lists is the point of asking.
D5 · What happens to a legacy project whose user clicks "Later"?
chosen
Dual resolution — root layout keeps working until migrated
Two layouts supported by one rule; new files always go under .frame/.
Force migration before use
Simpler code, but "Later" would leave the project half-usable (PR #116's deferred-then-conflict trap).
Why: the deterministic workflow must not break for anyone who defers; the scripts already resolve this way.
D6 · Pointer mechanism and Claude Code version floor
chosen
Only .claude/rules/frame.md; state the minimum version
Never collides with user files; Windows-safe; one mechanism.
Also write a root CLAUDE.md fallback when absent
Works on older Claude Code, but two mechanisms and a root file again.
Why: verified with claude -p on 2026-08-22; one mechanism beats two.
D7 · Gemini
chosen
Remove all GEMINI.md handling
Migration only removes a Frame-planted symlink.
Keep GEMINI.md symlink/consume
Support for a CLI that is being dropped.
Why: Gemini support is being removed (owner's call).

Technical decisions

D8 · What keys the frameStore API?
chosen
projectPath; projectId resolved inside
Zero churn at ~50 call sites and IPC payloads; id stored and exposed.
projectId; callers migrate
Cloud-ready signature, but a registry map and every caller change in this spec.
Why: the seam's job now is to be the only path-joiner; the backend swap later maps path→id internally. Spec D7 wording refined.
D9 · Test posture
chosen
Everything testable
Seven new node --test files incl. tree-walk init and a skippable claude -p native test; renderer excluded.
Pure logic only / none
Leaves git/fs paths and the migration engine — the riskiest code — unproven.
Why: the project's record covers src/main, src/shared, scripts; migration moves user data.
D10 · Renderer access to STRUCTURE.json
chosen
IPC LOAD_STRUCTURE_MAP via frameStore
One more channel; no renderer module joins a meta path.
Keep fs.readFileSync in structureMap.js with a new path
Smaller diff, but a second path-joiner and a broken S6 criterion.
Why: seam integrity is the point of the spec.
D11 · Hook entry form
chosen
sh -c '[ -f … ] && exec node …', literal string as marker
Silent on clones without .frame/bin; exact-match add/remove.
Unguarded node .frame/bin/spec-hint.js (today)
Errors on every prompt in a clone that lacks .frame/bin.
Why: scenario 5 (Frame-less teammate) must not see hook errors.
D12 · AGENTS.md during migration
chosen
Targeted line edit + review list
Preserves customisations; unmatched lines are reported, not forced.
Rewrite from template / leave as is
Rewrite destroys user edits; leaving it makes agents recreate root tasks.json.
Why: same reasoning ensureSpecDrivenArtifacts already records for this file.
D13 · In-flight footprints
chosen
Proceed: perf spec is finished (outcome.md present); cross-platform re-plans after
No blocking; cross-platform's plan must be refreshed on top of this.
Wait for both to close
Blocks on a status that is merely stale.
Why: audit-q3-performance-resources has outcome.md + measurements.md; audit-q3-cross-platform has not started.
